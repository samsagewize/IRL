# Contributing to IRL

Read the blockers and pilot flow in README.md. Work in feature branches and open pull requests explaining the behavior and how it was verified. Never seed live discovery with sample people or bypass authentication to make a feature appear complete.

Prioritize one complete experience: verified email, one real venue, time-limited presence, a welcome invitation, mutual acceptance, and an in-person hello. Include server-side authorization, blocks, reporting, and useful error/empty states.

Use synthetic accounts only in isolated test environments. Never put real user profiles, email addresses, location histories, reports, or credentials in public issues or test artifacts. Use private vulnerability reporting for security issues rather than disclosing sensitive details publicly.
